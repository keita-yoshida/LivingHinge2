# ゴールデン出力（出力リグレッションの安全網）

`tests/golden/` は、**その時点の `index.html` が実際に書き出す DXF / SVG そのもの**を保存したものです。
3Dプレビューの削除・Vite移植・リファクタリングなど「出力を変えないはずの改修」の前後でこれを照合し、
意図しない出力変化をバイト単位で検出します。

## 使い方

```sh
node tools/golden.mjs check     # 現行 index.html の出力がゴールデンと一致するか検証（CI 向け・差分があれば exit 1）
node tools/golden.mjs capture   # ゴールデンを採取し直す（= 出力を意図的に変えたときだけ実行）
```

`capture` は**出力仕様を意図的に変更したときにだけ**実行し、差分は必ずレビューしてからコミットしてください。
リファクタリングのついでに `capture` を回すと、安全網が消えます。

実ブラウザ（Chromium / Playwright）で `index.html` を読み込み、アプリ本体の
`regenerate()` → `makeDXF()` / `makeSVG()` / `buildTestSheet()` を直接呼んでいます。
つまりユーザーがダウンロードボタンを押したときとまったく同じ経路の出力です。

## 採取マトリクス（94ケース × DXF/SVG = 188ファイル）

| 区分 | 内容 | 件数 |
|---|---|---|
| `board__<pattern>__<preset>__<dir>` | 全11パターン × 3プリセット × 縦横 (120×70mm, 余白0, 外枠あり) | 66 |
| `margin2__<pattern>__std__v` | 余白 2mm（外周クリップの挙動を固定。tri は §7 で 2mm 以上推奨） | 11 |
| `noframe__straight__std__v` | 外枠なし | 1 |
| `extreme__spiral__{fine,coarse,odd}` | メアンダー極端値 cs=5/sw=0.8, cs=40/sw=5, cs=13/sw=1.7（CLAUDE.md §6.2 と同条件） | 3 |
| `size__straight__small` / `size__hex__large` | 20×20mm / 400×300mm（列配置とクリップの端条件） | 2 |
| `testsheet__<pattern>__std` | テストピース面付け（§7.5） | 11 |

`manifest.json` に各ケースの sha256・バイト数に加え、ポリライン数・総カット長・柔軟性スコア・
推定最小曲げ半径・使用パラメータを記録しています。**ファイルが差分ゼロでも manifest の統計値を見れば
何が変わったかの当たりが付く**ようにするためです。

## 既知の注意点

- **`file://` では採取しないこと。** ブラウザのキャッシュで編集が反映されない事故があるため（CLAUDE.md §6.3.5）、
  ツールは常に一時的な HTTP サーバ（127.0.0.1:8791）経由で読み込みます。
- Canvas のピクセル読み出し・スクリーンショットは使っていません（§6.3.5 のハング問題を回避）。
  照合対象はテキスト出力のみです。
- `bone` の DXF が突出して大きい（総カット長は straight の約2倍なのにサイズは約100倍）のは、
  モチーフ1個あたり 72分割の固定折れ線で書き出しているためです。曲線を解析形状のまま保持して
  弦公差ベースで離散化すれば大幅に縮みます（改修候補）。
